# Спека: «Момент чтения» (Reading Beat) — драматизация понимания на первом экране

**Дата:** 2026-07-27
**Issue:** #114 (редизайн, «объект — герой»), направление — доводка первого экрана до «первого wow».
**Статус:** дизайн одобрен владельцем (вариант A на связь фактов). Ждёт плана реализации.

## Проблема

Первый экран (#114) технически богат: объект-герой 132dp с превью, «дыхание»/аура (M1),
карточка «Point понял» с фактами построчно, пузыри «Самые вероятные». Но ко-фаундер ставит
«первый wow 5/10»: пользователь думает «ну и что теперь?» вместо «ого, он понял, что я дал».

Диагноз (по коду):
- Понимание **есть**, но подано как тихий чек-лист-«readout» (`UnderstoodSection`: `✓ Это
  покупка`, `✓ Нашёл телефон · …`) в **отдельной карточке под объектом** — оторвано от объекта.
- «Думание» сейчас — кольцо-импульс **вокруг** объекта (`AliveSurface`, принцип №3) + пульс-точка
  в карточке. Тихо. Свипа-чтения **по** объекту нет — а именно он в MOTION.md помечен как
  «чего нет» (принцип №3: «*заменить спиннер на световые импульсы по объекту*»).
- Итог: Point хорошо отвечает «**что можно сделать**», но недо-доставляет «**он понял, ЧТО это**».
  Wow живёт в моменте узнавания — сейчас он тихий и не на объекте.

## Цель

От «объект упал» до «понял» пользователь **видит** чтение. Момент узнавания становится felt-beat'ом
на самом объекте — прямой ответ «ну и что» → «ого, понял». Всё в рамках существующего языка
MOTION.md, без новых зависимостей.

## Дизайн

Три согласованных движения **по объекту** (не в оторванной карточке) + финальная точка.

### ① Свип-чтение по объекту (принцип №3)
Пока идёт обогащение (`thinking == true`), по поверхности героя проходит мягкая световая полоса —
как сканер читает. **Заменяет** текущее кольцо-импульс вокруг (один ясный сигнал «чтения», не два
конкурирующих). Направление/темп — от физики типа (принцип №6):
- документ/текст/URL/PDF/office → строго **сверху вниз** (читаем строки), чётче;
- фото (IMAGE) → мягкий **диагональный** отблеск.

Реализация: полоса-градиент (брендовый тон, низкая α), анимируемая по bounds героя, **клип по форме
героя** (RoundedCornerShape 26dp), поверх контента через `drawWithContent`/`graphicsLayer`. Живёт
только пока `thinking` (батарея). Работает и для превью, и для icon-плашки (у text/url превью нет —
свип идёт по плашке типа).

### ② Факты зажигаются от объекта (принципы №1 «рождается» + №4 «частицы от объекта») — вариант A
Каждый факт при появлении (`FactRow`) не просто фейдится: **✓ ярко вспыхивает**, строка на миг
подсвечивается брендовым и оседает — синхронно с лёгким «пингом»-вспышкой на объекте. Понимание
визуально идёт **из** объекта.

**Вариант A (выбран для v1):** вспышка-ignite на месте строки + пинг на объекте. Без общей системы
координат объект↔карточка. Дёшево, вкусно.
**Вариант B (follow-up):** искра физически летит от объекта к строке (оверлей-слой + общие
координаты). Не в этом срезе.

### ③ Аура разгорается по мере понимания (принцип №10, усиление текущего)
Сейчас аура = 0→1 на первом факте (вкл/выкл). Делаем **рамп** по числу фактов: объект «просыпается»
по мере узнавания. Чистая функция `auraLevel(factCount)`:
- `0` фактов → `0f`;
- иначе → `minOf(1f, 0.55f + 0.15f * (factCount - 1))` (1 факт → 0.55 «уже тёплый»; 4+ → 1.0).

### ④ Финальная точка «он понял»
Когда обогащение кончилось (`thinking` стал `false`) и есть ≥1 факт: свип делает **последний проход
и гаснет**, аура фиксируется на своём `auraLevel`. Это визуальная точка. (Хаптика/звук финала —
принцип №7, срез M4, **не сюда**.)

## Инварианты (соблюдены)
- **≤300 мс до интерактива**: свип/факты украшают уже готовый экран; `thinking` включается async,
  когда стартует обогащение (после первой отрисовки). Никаких блокирующих enter-хореографий.
- **Reduced motion** (`rememberMotionEnabled() == false`): свип off, факты появляются на месте, аура
  сразу на финальном `auraLevel`. Единый гейт, уже есть.
- **Батарея**: свип — `InfiniteTransition`, жив только пока `thinking` и окно в фокусе.
- **«Движение объясняет модель»**: каждый элемент маппится на принцип MOTION.md (№3/№10/№1/№4/№6).
  Ничего декоративного сверх смысла.

- **`core/ui/UnderstoodSection.kt` → `FactRow`**: добавить ignite-вспышку при появлении (усилить

## Тестирование
- **Pure-функции — юнит** (как `breathSpecFor`, в `core/ui` тестах): `readingSweepSpecFor` (документ
  → vertical=true; IMAGE → vertical=false), `auraLevel` (0→0f; 1→0.55f; насыщение к 1f; монотонность).
- **Хореография** — не юнит (визуально): `@Preview` + живьём на устройстве.
- TDD: pure-функции RED→GREEN до реализации свипа/ауры.

## Скоуп (YAGNI)
- **В срезе:** свип-чтение + аура-рамп + ignite-вспышка (вариант A) + финальная точка.
- **Не в срезе (follow-up):** частица-искра объект→факт (вариант B); звук/хаптика финала (срез M4);
  живой фон (M5). Морф-переходы (M3) — отдельно.

## Крайние случаи
- **Нет превью** (text/url/office без превью): свип идёт по icon-плашке типа — «читается» любой
  объект. `AliveSurface` оборачивает контент, оверлей на нём же.
- **Обогащение не нашло фактов**: свип отработал пока `thinking`, затем погас; аура остаётся 0
  (нет фактов — нет ложного «понял»). Объект возвращается к спокойному дыханию. Честно.
- **Очень быстрое обогащение**: хотя бы один проход свипа; минимальную длительность не форсируем (YAGNI).
- **Много фактов**: аура рампится по `auraLevel`; ignite — на каждый `FactRow` (уже `key`-нут).
