# Точки входа: где рождается объект (#248, #246, #249, #251, #259)

Проработано 03.08.2026 с владельцем. Решения приняты им и помечены ниже как **решено**.

## Зачем

Point отвечает на вопрос «что я могу сделать с этим объектом». Значит его сила — не в новой
функции, а в новой **двери**: месте, где объект рождается. Сегодня дверей пять, и все они
достались фазе 2 (`ROADMAP.md`): Share, лаунчер, правый клик по тексту (`PROCESS_TEXT`),
QS-плитка «Общий буфер» (синк с ПК, объект не рождает), QR-схема `point-pc://`.

Не хватает трёх, названных владельцем в #248 как самые сильные: «Открыть с помощью Point»,
шторка, которая создаёт объект, и виртуальный принтер.

## Что уже есть — на это опираемся, а не строим заново

- **Единая ручка флоу.** Любой вход добывает `Uri` + MIME и зовёт `FlowViewModel.onShared(...)`.
  Так делают `ShareActivity` и `ProcessTextActivity`. Новые двери — не новая механика.
- **Приём буфера из шторки.** `ClipboardTileService` → `ClipboardSyncActivity`: мгновенная
  прозрачная активити существует ровно потому, что Android отдаёт буфер только приложению на
  переднем плане. Тот же приём годится для новых источников.
- **Выделение области.** `SelectionScreen`, `openSelection`/`takeSelection`, и главное —
  `fragmentCapture`, который вырезает обведённое в JPEG. Механика написана.
- **Ноль разрешений.** В манифесте `:app` сегодня нет ни одного `uses-permission`. Приложение не
  просит у человека ничего — это часть границы приватности из `CLAUDE.md`, и терять её задаром
  нельзя.

## Решения владельца

| вопрос | решение |
|---|---|
| Конструкция шторки | **Одна плитка → экран выбора источника.** Не плитка на каждый источник |
| Источники | Камера, буфер, голос, локация. **Уведомления — нет. Экран — нет** (#64) |
| Чем добывать | **Чужими руками:** системная камера и диктофон; своё — только там, где иначе никак |
| «Открыть с помощью» | **`*/*` — всё подряд.** Риск «всегда открывать в Point» принят осознанно |
| Принтер | **Делаем**, на Android через `PrintService`. Windows-принтер — не в этот заход |
| Выделение области | **Работает без распознавания.** Обводить кадр можно сразу, OCR не условие |

## Архитектура

### Дверь ничего не решает — она добывает

```
дверь (Activity/Service)  →  Uri + MIME  →  FlowViewModel.onShared(...)  →  обычный флоу
```

Шторка передаёт добытое в `ShareActivity` внутренним `ACTION_SEND`, а не хостит флоу сама. Это
дословно требование #246: «шторка никогда не выполняет Capability — только создаёт объект».

### Контракт источника

Новый контракт `ObjectSource` живёт в `:app`, **не в core**: источники по природе завязаны на
Android (камера, буфер, диктофон), и тащить это в Android-free модули нельзя.

```kotlin
interface ObjectSource {
    val id: String
    val label: String                       // «Камера», «Буфер обмена», «Голос», …
    fun isAvailable(context: Context): Boolean   // нет системного приложения — плашки нет
    fun request(context: Context): Intent?       // null — добываем сами, без чужой активити
    suspend fun read(context: Context, result: ActivityResult?): Produced?
}

data class Produced(val uri: String, val mime: String)
```

Регистрация — Hilt `@IntoSet`, как у Capability. Экран выбора строится из набора: добавить
источник = добавить класс, разметку править не нужно.

### Общий хост — попутная уборка

`ShareActivity` (128 строк) и `ProcessTextActivity` (107) почти совпадают: в каждой свой список
из ~43 колбэков `PointHost`. Третья дверь сделала бы три копии. Общая часть выносится в базовый
класс `FlowHostActivity`; каждой двери остаётся разбор своего intent.

## Двери по одной

### 1. «Открыть с помощью Point» (#249)

`ACTION_VIEW`, `mimeType="*/*"`, схемы `content://` и `file://`. В разборе intent — ветка `VIEW`:
объект берётся из `intent.data`, MIME добирается у `ContentResolver`, дальше — та же `onShared`.

Цена, принятая владельцем: человек может выбрать «всегда», и Point станет обработчиком по
умолчанию для типа, просмотрщиком которого он не является. Смягчение: на незнакомом типе экран не
пустой — поделиться, сохранить и «открыть в другом приложении» принимают любой файл.

### 2. Шторка (#246)

Плитка «Point» → прозрачная `SourcePickerActivity`: «Что превратить в объект?» и плашки
источников в стилистике портала. Существующая плитка «Общий буфер» (#161) остаётся — это другая
функция.

| источник | чем добывается | новое разрешение |
|---|---|---|
| Камера | системная камера, `ACTION_IMAGE_CAPTURE`, кадр в `cache/capture` | нет |
| Буфер | чтение на переднем плане (приём из `ClipboardSyncActivity`) | нет |
| Голос | системный диктофон, `RECORD_SOUND_ACTION` | нет |
| Локация | `LocationManager`; объект — `text/plain` с координатами и адресом, если система его дала | `ACCESS_FINE_LOCATION` |

**Экрана в этом списке нет — и не будет.** Первая редакция спеки предлагала `MediaProjection`, и
это была ошибка проработки: путь «прочитать текущий экран» закрыт **навсегда** решением владельца
(`DECISIONS.md`, «Захват экрана = только скриншот», #64) — policy-риск Google Play и трение
согласий не окупают выгоды. Владелец подтвердил его снова 03.08.2026 словами «MediaProjection
опасно, не делаем».

Замена уже работает и ничего не стоит: системный скриншот, расшаренный в Point. С этим срезом он
стал сильнее — скриншот приходит и через «Открыть с помощью» (#249), а обвести на нём нужное можно
не распознавая (#259).

**Голос упирается в #223.** Пока Point не разбирает `ogg`, объект-голос можно сохранить и
переслать, но не «понять». Это называется человеку, а не выдаётся за готовое.

### 3. Принтер (#251)

Point объявляет виртуальный принтер через `PrintService`: любое приложение печатает в него,
задание приходит готовым PDF и становится объектом. Покрывает всё, откуда нормального экспорта
нет, — банк, госуслуги, почтовые клиенты.

Цена: службу печати человек включает один раз руками (Настройки → Печать → Point) — сама она не
появится. `BIND_PRINT_SERVICE` объявляется на сервисе и диалогом доступа не является.

Виртуальный принтер для Windows требует драйвера уровня системы — это работа десктопа, в этот
заход не идёт.

## Выделение области без распознавания (#259)

Владелец: «выделение для того и надо — кто сказал, что мне нужен OCR?» Возражение верное: сейчас
выделение открывается **только** при наличии слоя слов, потому что задумывалось как способ выбрать
*текст* (атомы внутри области). Но человеку нужно выбрать *область* — и до всякого чтения.

Механика для этого уже есть: `takeSelection` вызывает `fragmentCapture`, когда в выделении нет
текста, и вырезает обведённое в JPEG. Мешают ровно две проверки:

1. `PointHost.onHeroTap` — открывает выделение только при `META_OCR_ATOMS_REF`, иначе просто
   открывает объект;
2. `FlowViewModel.openSelection` — выходит, если слоя нет.

Снимаются обе. Слой становится **необязательным**: есть — рамка прилипает к словам и выделение
даёт текст (как сейчас); нет — рамка свободная, и выделение даёт кадр. Это же делает снимок экрана
полезным сразу: снял → обвёл нужное → получил объект, а распознавать или нет — решает человек.

## Отказы

Каждый отказ называется словами и не притворяется успехом:

- нет системного приложения для источника — плашка не показывается вовсе;
- человек отменил съёмку или запись — молча возвращаемся, без «Готово» (правило исхода из #358:
  у отменённого знака нет);
- буфер пуст — «в буфере пусто»;
- в локации отказано — так и говорим, без повторных запросов;
- задание печати не прочиталось — честная ошибка, а не пустой объект.

## Тестирование

На JVM (без устройства): выбор доступных источников, разбор `VIEW`-intent, превращение результата
источника в `Uri` + MIME, поведение выделения без слоя слов.

Живьём — только руками владельца: на его A34 система не даёт ни читать буфер через кабель, ни
запускать неэкспортированные активити, поэтому плитка, буфер и печать проверяются вручную.
Автоматическая проверка на эмуляторе покрывает «Открыть с помощью» и выделение.

## Чего этот заход не делает

- **Уведомления как источник** — нужен доступ ко всем уведомлениям человека; это против принципа
  самого #246 («никакого чтения чужого UI») и против политики Play.
- **Захват экрана** — закрыт решением #64 и подтверждён владельцем 03.08.2026. Вместо него —
  системный скриншот, расшаренный в Point.
- **Входы на ПК** (#250, #252–#255) — другой пласт, десктопная работа.
- **Windows-принтер** — драйвер уровня системы.
