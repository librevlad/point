## Правило статуса

Разрешены ровно пять статусов.

| статус | когда ставится |
|---|---|
| `PASS` | клетка пройдена живьём, есть доказательство, наблюдаемое поведение совпало с ожидаемым |
| `FAIL` | клетка пройдена живьём, есть доказательство, поведение разошлось с ожидаемым |
| `BLOCKED` | пройти **невозможно**: нет устройства, сервера, ключа, данных, разрешения или поверхность физически недостижима. Причина обязательна и выносится в раздел Blocked |
| `NEEDS INVESTIGATION` | клетка пройдена, но наблюдение не позволяет назвать исход: поведение неоднозначно, доказательства противоречат друг другу, причина не установлена |
| `N/A` | клетка **не существует** в продукте: сочетание недостижимо или бессмысленно. Основание обязательно |

Шестого статуса нет. `—` в колонке `STATUS` — **не статус, а его отсутствие**: строка заведена,
клетка применима, прогон по ней ещё не выполнялся. Такая клетка не является ни `PASS`, ни
`BLOCKED`, ни `N/A`.

**Запрещено.** «probably pass» · «assumed pass» · «покрыто по аналогии» · «скорее всего работает» ·
«код выглядит правильно» · «зелёные тесты значит работает». Клетка без доказательства — не `PASS`.

**`BLOCKED` — не синоним «ещё не дошли».** `BLOCKED` означает невозможность, а не очередь.
Непройденная, но проходимая клетка остаётся `—`.

**`N/A` — не синоним «не проверяли».** `N/A` означает несуществование клетки, а не отсутствие
теста. Пометить непройденную клетку `N/A` — подлог покрытия.

## Формула покрытия

```
TESTED     = PASS + FAIL
APPLICABLE = PASS + FAIL + BLOCKED + NEEDS INVESTIGATION
COVERAGE   = TESTED / APPLICABLE
```

- `BLOCKED` и `NEEDS INVESTIGATION` покрытием **не** считаются: они в знаменателе, но не в числителе.
- `N/A` в знаменатель **не** входит.

**Форма формулы во время прогона.** Формула выше — закрывающая: она верна, когда клеток `—` не
осталось. Пока прогон идёт, клетки `—` применимы и остаются в знаменателе:

```
APPLICABLE = PASS + FAIL + BLOCKED + NEEDS INVESTIGATION + (—)
```

Обе записи совпадают в момент закрытия, когда `(—) = 0`. Так покрытие невозможно поднять,
не пройдя клетку: непройденное всегда давит на знаменатель, а `0 / 0` никогда не превращается
в «100 %».

**100 % достигнуто**, когда каждая применимая клетка имеет `PASS` или `FAIL` с доказательством.
Пока остаётся хоть одна применимая непройденная клетка, объявлять «100 %» нельзя.

## Правило эквивалентности

Матрица не является тупым перемножением параметров, но и сведение клеток не делается словом
«аналогично». Свести несколько потенциальных клеток в одну можно **только** записью в разделе
Equivalence Decisions, содержащей все четыре поля:

```
REASON FOR EQUIVALENCE
CODE PATH
SAME STATE TRANSITION
NO DIFFERENTIATING FACTOR
```

Если различается хотя бы один значимый фактор — вид объекта, представление, устройство
(телефон/компьютер), capability, resolver, realizer, провайдер, сеть, разрешение, настройка,
стадия жизненного цикла, источник или состояние графа — это отдельная клетка со своим
доказательством.

## Как читать колонки

- `GRAPH TRANSITION` — ожидаемый переход графа. `N/A` в этой колонке означает чисто визуальное
  состояние без перехода графа (#969) и **не** является статусом строки.
- `EVIDENCE` — ссылка на доказательство: снимок экрана, снимок графа до/после, строка журнала ПК
  (`~/.point-pc/journal`), ответ сервера, `llm-log`. Клетка без снимков графа до и после не может
  быть `PASS` там, где переход графа применим (#974).
- `BUG / ISSUE` — карточка находки. Один `FAIL` может ссылаться на несколько карточек.
