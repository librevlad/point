# Мета-аудит /live-review #967 — независимая проверка матрицы покрытия

**Дата аудита:** 17.08.2026. **Объект:** `docs/audits/live-review-967-coverage.md` на коммите `52c3312`
(+ правка GRF-062 → #1074). **Что делалось:** построчное чтение всех 539 строк матрицы по одному
правилу (см. ниже), независимый пересчёт покрытия, проверка каждого `N/A` и `BLOCKED`, поиск строк без
доказательства, PASS без графа до/после, PASS «только экран», односторонних PASS в двусторонних клетках,
серверных PASS без клиентской половины, дыр инвентаря, class expansion у дефектов, отражения карточек
#988–#1067, арифметики. Баги продукта здесь не чинятся, эпик не закрывается.

**Правило судейства** — правила самой матрицы («Правило статуса», «Как читать колонки», #974, #979):
PASS только с наблюдением живьём; там, где `GRAPH TRANSITION` применим, — снимки графа до и после;
двусторонние клетки — обе стороны; серверные — вся цепочка до экрана; `N/A` = клетки нет, `BLOCKED` =
проверить невозможно.

## 4. `BLOCKED`

SRV-064, DRP-015 — причина названа (боевой сервер, локального не бывает — решение владельца 17.08), компенсация
приведена. Построчный проход, однако, оспаривает обе (см. FALSE BLOCKED в разделе 7):
- SRV-064: прогон 14.08 закрывал 27 серверных клеток на **живом локальном ASGI поверх настоящего SQLite**
  (таблица «Прогоны») — то есть локальный экземпляр для проверок существовал, и перезапуск на нём возможен.
  «Локального не бывает» верно про эксплуатацию, но не про стенд проверки. Клетка остаётся BLOCKED только
  как решение владельца, не как невозможность.
- DRP-015: аргумент «отказ сервера уже наблюдался в DRP-007 (507)» аудитор считает слабым — 507 это отказ по
  размеру при живом сервере, а клетка про недоступный сервер; BLOCKED здесь обоснован сильнее.
Оба случая — на решение владельца.
