# Point — спринты до 1.0

Метод принят из #113: **Vision → Epic → Milestone → Sprint → Task**.

**Правило спринта (с оговоркой D33):** спринт заканчивается **демонстрируемым артефактом**,
который можно показать человеку за 30 секунд. Не обязательно фичей — «релизная сборка стоит
на телефоне и проходит смоук» годится. «Отрефакторили», «подготовили» — нет.

Согласовано с: `STATUS.md` (что есть), `docs/designs/path-to-0.3.md` (блокеры и решения
D5–D22), `IDEAS-AUDIT.md` (вердикты D24–D34), `ROADMAP.md` (фазы платформы).

---

## Vision

> Point — Object Runtime. «Правая кнопка для всего».
> `Object → Intent → Capability → Realizer → Object`.
> Point **никогда не строит автоматические цепочки** — пользователь всегда контролирует.
> Северная звезда: каждый релиз уменьшает число переключений между приложениями.

**Демо:** `gh issue list` показывает реальную очередь; `STATUS.md` сходится с кодом.

### Спринт A1 — «Сборка существует»
Первая в истории проекта релизная сборка.

- R8 и `shrinkResources` выключить (D11) — вместе с первым `bundleRelease`, одним изменением
- Собрать `bundleRelease`, поставить на **физическое устройство**
- Проверить реальный размер APK (24.5 МБ в доке против ~47 МБ по оценке консилиума)
- CI: `strategy.matrix.os` — Android и бот на `ubuntu-latest`, MSI на `windows-latest`
- CI: smoke-run каждого артефакта, а не только успешная компиляция

**Демо:** телефон в руке, приложение из релизной сборки, смоук пройден.

### Спринт A2 — «Ничего не утекает»
Ни один секрет не покидает машину.

- Граница секретов: **общее правило и общий тест**, код сборки остаётся в модулях (D21)
- Релизные сборки `:app` и `:desktop` не читают ключи из `local.properties`; debug сохраняет путь
- Секрет вон из `RelayEnv.kt` и MSI-установщика
- Отозвать и ротировать все действующие ключи

**Демо:** `strings` по собранному APK и MSI — ноль ключей. Вернуть ключ — тест краснеет.

### Спринт A3 — «Человек понимает продукт»
Тот самый первый wow, которого сейчас 5/10.

- Песочница первого запуска: **реальный корпус образцов** (не заглушки), лимит размера,
  один источник истины с интеграционными тестами
- AI-шаги на записанных ответах LLM — демо работает без сети и без ключа, честно помечено
- Перенос `SandboxActivity` из `debug` в `main`, **ровно одна иконка** в лаунчере
- Читаемость графа: подпись «→ станет X» **с глушением при `expectedNextState == state`**,
  следующий шаг после Done (топ-2 из реестра по состоянию до Done)

**Демо:** даёшь телефон человеку без объяснений — за 60 секунд он сделал действие и понял продукт.

### Спринт A4 — «Ошибки видны»
Ни одного молчаливого отказа.

- Пять тихих отказов получают имя, код ответа и видимое человеку сообщение
- Дедлайн фолбэк-цепочки выводится из таймаута вызывающего + **явная политика** при истечении

**Демо:** выключаешь сеть, забиваешь диск — человек видит внятный текст, а не тишину.

### Спринт A5 — «Можно загрузить»
- Data Safety и обоснование пяти разрешений из merged-манифеста
- Хостинг политики приватности, URL в листинге
- `versionCode` 1→2, `versionName` → `0.3.0`, свести с `packageVersion` десктопа
- `apksigner verify --print-certs`, бэкап keystore, пароли записаны

**Демо:** черновик релиза в Play Console, все проверки зелёные.

# ПОЕЗД C — ПК и релей (не блокирует A)

### Спринт C0 — «Порт открыт» (вручную, до кода)
Правило фаервола `tcp:8443` в GCP Web Console. `gcloud` на инстансе прав не имеет — кодом
нерешаемо. **Демо:** запрос к релею с внешнего адреса возвращает `/health`.

### Спринт C1 — «ПК не падает»
Разобрать `EXCEPTION_ACCESS_VIOLATION` в `skiko-windows-x64.dll` или доказать как разовый
артефакт среды. **Демо:** десктоп запускается и живёт под нагрузкой.

### Спринт C2 — «Релей выдерживает интернет»
- `certbot` + Let's Encrypt вместо пиннинга самоподписа, супервизор вместо `crontab @reboot`
- Версия и в пути (`/v1/mbx`), **и в схеме сообщения**
- Лимит одновременных соединений + быстрый 503; квота на mailbox; лимит диска
- Тесты `relay.py` + Python в CI

**Демо:** сканер портов не роняет релей; старый клиент получает внятный отказ по версии.
