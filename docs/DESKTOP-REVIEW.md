# Point для ПК: ревью по замыслу, а не по симптомам

Сверено **06.08.2026** с первоисточником (#112 «первое вау», #147 «Continue on PC»), с кодом и с
**состоянием машины владельца** — не по впечатлению.

Первая версия этого разбора нашла шесть дефектов и была признана владельцем «десятью процентами
проблемы». Она и была ими: чинила симптомы, не сверившись с замыслом. Здесь — сверка.

## Чем Point на ПК должен быть

Дословно из видения (#112) и постановки (#147):

> **Continue on PC.** Через секунду объект появляется на компьютере. **Без регистрации.** Это
> должно работать настолько хорошо, чтобы люди рассказывали о нём другим.

> **Point Free — «Правая кнопка для всего».** Пользователь должен привыкнуть: «любой объект
> сначала открываю в Point».

Отсюда три обещания, по которым и надо судить:

1. **Секунда и без регистрации** — магия показывается сразу, показать её можно кому угодно.
2. **Объект приходит готовым к работе** — с пониманием, а не голым файлом.
3. **Point на ПК — слой над всем**, а не отдельная программа со своим окном.

## Р1. Регистрация стала обязательной — обещание нарушено прямо

ТЗ: «без регистрации». Сейчас **оба устройства обязаны войти в Google-аккаунт**, иначе связи нет
вовсе: круг устройств строится сервером, ящики адресуются по `user_id`, ключи устройств едут через
`/enroll`.

Это осознанная замена релея на сервер аккаунтов (#413, #471) — но вместе с ней тихо исчезло
условие, ради которого «Continue on PC» вообще был назван «первым вау». **Показать магию другу
теперь нельзя**: сначала заведи ему аккаунт.

Здесь нужно решение владельца, а не правка кода: либо обещание меняется в спеке, либо возвращается
путь без аккаунта (одноразовая пара «телефон ↔ этот компьютер»).

## Р2. Point на ПК не встроен в систему — привычка «сначала в Point» невозможна

На телефоне Point живёт в системном «Поделиться» — он доступен **везде**. На компьютере он живёт
только в своём окне.

Проверено на машине владельца:

```
HKCU:\Software\Classes\*\shell\Point       → False
SendTo\                                    → Point отсутствует
глобальный хоткей                          → в коде нет
```

Задача #252 («Send to Point» в контекстное меню) **закрыта**, но в системе пункта нет: сделан приём
файла из аргументов командной строки (`SendToRunning`), а регистрации в реестре или в `SendTo` не
делает никто — ни код, ни установщик (`menu = true` у jpackage это меню «Пуск», не контекстное).

Пока этого нет, «любой объект сначала открываю в Point» на ПК не может стать привычкой: чтобы
что-то сделать, надо открыть окно и перетащить туда файл.

## Р3. Работа на компьютере обрывается после первого действия

`DesktopState.perform` не обрабатывает `ActionResult.Success` — этого слова нет в файле ни разу.
Результату действия некуда деться, кроме очереди на телефон, поэтому «Сделать легче» отдаёт сжатый
файл **на телефон**, а на ПК остаётся исходный.

Журнал настоящей работы владельца:

```
ok      Сделать легче        Было 1.0 МБ, стало 124 КБ · 1920×873
ПРОВАЛ  Прочитать в облаке   Снимок 1 МБ — сервис принимает до 1 МБ. Сначала «Сделать легче».
```

Формула `Object → Action → Object` на второй поверхности теряет последнюю стрелку. → **#595**

## Р4. Компьютер не убирает за собой ничего

Главный инвариант приватности телефона: объект копируется в рабочую папку и **стирается по
окончании работы**. На ПК такого правила нет вовсе — в `Inbox` и `DesktopState` нет ни одного
удаления.

На машине владельца, `~/Point`:

```
23 файла, 12 МБ, самому старому 11 дней
Screenshot_20260729_095332_Authenticator.jpg   ← коды двухфакторной аутентификации
Screenshot_20260722_115847_Viber.jpg           ← переписка
photo_receipt.jpg, документ.docx, 3 копии одного фото
```

Через эту дверь идёт то же, что через телефон: чеки, переписка, коды. Разница в том, что на
телефоне это стирается, а на компьютере лежит неделями. Это и есть «забирает лишние файлы» (#598),
только хуже — не забирает, а **накапливает**.

## Р5. Имя объекта становится именем файла

В той же папке:

```
Счёт 4512 от ООО Ромашка. Оплатить до 20…     ← многоточие в имени файла, расширения нет
объект                                          ← безымянный
20260728_101726 (2).jpg, (3).jpg                ← один файл принят трижды
```

Имя объекта — свойство объекта, имя файла — свойство диска; на телефоне это разделено (#533,
#581), на ПК склеено. Отсюда файлы без расширения (их не открыть двойным щелчком) и копии.

## Р6. Отказы и исходы говорят канцелярски

«Снимок 1 МБ — сервис принимает до 1 МБ» (граница `>`, округление съело разницу — читается как
ложь). «В очереди „Microsoft Print To PDF" · проверьте принтер» — человек не понимает, ушла ли
печать. → **#596**

## Р7. Действия телефона лягут свалкой

После симметрии (#588) телефон объявляет компьютеру больше двадцати действий вместо двух — плоским
списком, без групп и порядка. → **#597**

## Р8. Понятое показано следами разбора (исправлено 06.08.2026)

`Amount.src · ocr`, `Amount.ev · semantic` — улики разбора вместо фактов. Починено фильтром по
форме ключа, с тестом.

## Почему это не поймали 112 зелёных тестов

Замер по коду: **256 тестов проверяют один шаг, 8 — цепочку из двух и более. Три процента.** Ни
один не спросил «что человек увидит следующим шагом» — поэтому обрыв цепочки (Р3) не был виден.
→ **#599**
