# Point — путь к публичному релизу

Этот документ держит **ворота и порядок**. Ничего больше.

Переписан 2026-07-29 после сверки, которая нашла в прежней версии девять неверных строк из
сорока двух и незнание пятнадцати функциональных областей: он отстал от кода на 146 коммитов
за шесть дней. Причина была не в лени, а в жанре — документ пытался быть одновременно
инвентарём, статусом и планом, и разошёлся по всем трём осям сразу.

**Правило, введённое чтобы это не повторилось:**

| Вопрос | Единственный источник истины |
|---|---|
| Что есть в продукте | **код**; собранный из него инвентарь — `STATUS.md` |
| Что делается | **GitHub Issues**; метка обязательна, без метки это не задача |
| В каком порядке | `SPRINTS.md` |
| Почему так решено | `DECISIONS.md` |
| Куда движемся как платформа | `ROADMAP.md` |
| Как ведём работу | `OPERATING-MODEL.md` |

**Этот документ не утверждает готовность.** Готовность проверяется по коду и по собранному
артефакту. Включённый флаг результатом не является — это правило появилось после того, как
release-hardening дважды считался закрытым по флагу при том, что релизная сборка ни разу не
собиралась.

---

## Где мы на самом деле

Функционально продукт **больше**, чем описывал его собственный план: 44 действия, три
поверхности, кросс-сетевой канал. Незакрытого функционала мало.

Незакрыт **выпуск**:

```
git tag     → 0        versionCode  → 1
gh release  → пусто    versionName  → "0.2.0"
bundleRelease         → ни разу не собиралась
```

**Продукт построен, но ни разу не проверен как продукт.**

## Ворота 0.3

Три релизных поезда (решение D12). **Обязателен только поезд A** — нативный краш на Windows
не должен останавливать выкладку Android-приложения.

### Поезд A — Android. Ворота выпуска

Ни один пункт не «желателен». Пока не выполнены все — не выкладываем.

1. **Релизная сборка существует и проверена на физическом устройстве.** `bundleRelease`
   собран, установлен, смоук пройден: image → скан → PDF; PDF → OCR; мульти-шаринг →
   COLLECTION → merge; распаковка архива; AI без ключа даёт понятное «нужен ключ», с ключом
   работает; песочница проходится целиком; сворачивание посреди флоу и возврат ничего не теряют.
2. **Ни одного секрета в артефакте.** `strings` по APK — ноль ключей. Возврат ключа роняет тест.
3. **Ровно одна иконка** Point в лаунчере.
4. **Ноль крашей** за полный проход смоука; `CrashLog.pending()` пуст.
5. **Два устройства минимум**: современное (Android 14+) и на `minSdk = 26`.
6. `apksigner verify --print-certs` показывает релизный сертификат, не дебажный.
7. **Data Safety заполнена**, разрешения обоснованы, URL политики приватности опубликован.
8. **Ни одного молчаливого отказа** на путях смоука: у каждой ошибки есть видимый человеку текст.

**Явно НЕ входит в ворота 0.3:** минификация R8 (выключена решением D11, возвращается в 0.4
с проверенными keep-правилами) · канал краш-отчётов от живых людей (принятое последствие) ·
structured output · Capability Packs.

#### Порядок выпуска (после аварии v0.2.0 — #306)

Тег `v*` запускает `.github/workflows/release.yml`: чистый раннер (без `local.properties` —
ключам неоткуда взяться) собирает **только** release-варианты (APK + desktop-MSI), ворота
до публикации отсекают всё отладочное (имя, debuggable-флаг, отладочная подпись) и сканируют
содержимое на формы секретов (`tools/release-scan.sh` — последний рубеж, не основная защита).
Результат — **черновик** релиза с чек-листом; публикует человек. Подписанный релизным ключом
APK собирается локально и перед приложением к релизу прогоняется тем же сканом — ассет мимо
скана и был аварией v0.2.0.

### Поезд B — Telegram-бот. Ворота

- AI-действия строго BYOK: чужой человек не жжёт твою квоту.
- Скан, OCR, merge, QR работают без ключа.
- Диск не растёт: очистка по окончании флоу плюс TTL-свип.

### Поезд C — ПК и релей. Ворота

- Порт `tcp:8443` открыт (**вручную в GCP Console**, `gcloud` на инстансе прав не имеет).
- Краш Skia разобран или доказан как разовый артефакт среды.
- Сертификат автообновляемый (Let's Encrypt), пиннинг самоподписа снят.
- Релей переживает сканер портов: лимит соединений и быстрый 503.
- Версия и в пути, и в схеме сообщения.

## Откат

| Поверхность | Механизм | Скорость |
|---|---|---|
| Android / Play | Halt staged rollout; назад на предыдущий `versionCode` **нельзя** — только новый выпуск | часы |
| Бот | Остановить процесс | минуты |
| Релей | Остановить процесс; клиенты падают в LAN-режим (#193) | минуты |
| ПК-компаньон | **Отката нет** — установщик уже у человека | только новая сборка |

Следствие: логику, которую может понадобиться выключить, держим на серверной стороне —
она гасится без обновления клиента. У ПК-двери отката нет вообще, поэтому она едет
отдельным поездом.

## Критерии успеха 0.3

Замеряется через `UsageJournal` и логи бота.

- **Первичный:** доля установок, где человек **завершил хотя бы одну цепочку**
  объект → действие → результат. Прямое измерение того, понята ли модель продукта.
- **Вторичный:** возврат на второй день · завершённых Share-сессий на пользователя ·
  конверсия в BYOK.
- **Отдельный гейт:** ни одна работа плана не проверяет, **понял ли** новый пользователь
  модель «объект → действия». Перед объявлением релиза успешным — проверка на живых людях,
  не на себе.
