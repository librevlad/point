# Тестирование без перезаливки APK

Полная переустановка APK на каждую правку — медленно. Здесь петли, которые её
избегают, от самой быстрой к самой полной.

## 1. Compose `@Preview` — вообще без устройства и без APK ⭐

Первый экран и пузырьки — чистые, stateless composable'ы, поэтому рендерятся
прямо в Android Studio.

- Открой `core/ui/.../FirstScreenPreview.kt`, включи **Split / Design** (правый
  верхний угол редактора).
- Правишь `FirstScreen`/`BubbleItem`/тему → превью перерисовывается на лету
  (иногда нужен «Build & Refresh» в панели превью).
- Готовые превью: Image, PDF, Zip, Text+ошибка, Image·dark. Добавляй свои —
  просто ещё одна `@Preview`-функция с нужными данными.

Это основной инструмент для итераций по **виду** UI. Ноль сборки приложения.

## 2. SandboxActivity + Apply Changes / Live Edit — на устройстве, без переустановки

Для проверки **поведения** (ingest → классификация → пузырьки, Back по стеку) на
реальном устройстве/эмуляторе, но без пере-flash'а:

1. Один раз поставь **debug**-сборку (`:app:installDebug` или Run). В лаунчере
   появится иконка **«Point Sandbox»** (только в debug — в release её нет).
2. Запусти её: меню с примерами объектов (Текст / Картинка / PDF / ZIP / Ссылка).
   Тап → тот же реальный флоу, что и из системного Share, но без «расшаривания».
3. Дальше меняй код и жми:
   - **Apply Changes (Ctrl+Alt+F10 / ⌃⌘R)** — код в запущенное приложение без
     переустановки;
   - **Live Edit** — правки Compose-функций подхватываются почти мгновенно.

Полный Run/переустановка нужен редко — в основном при смене манифеста, Hilt-графа
или сигнатур DI.

> Почему Sandbox, а не системный Share: не нужно каждый раз искать файл и жать
> «Поделиться». Кнопка = мгновенный объект нужного типа.

## 3. JVM unit-тесты — логика без эмулятора

Чистые модули тестируются на JVM, без Android:

```bash
./gradlew :core:model:test :core:flow:test :executors:test
```

Покрыто: классификация состояния (`ObjectClassifierTest`), вывод графа/пузырьков
из контрактов (`DefaultExecutorRegistryTest`), иммутабельность модели. Пиши сюда
всё, что не требует Android framework, — это самый быстрый и надёжный контур.

## 4. (Рекомендация на потом) Screenshot-тесты на JVM — Paparazzi

Чтобы **вид** проверялся в CI без эмулятора, добавь
[Paparazzi](https://github.com/cashapp/paparazzi): он рендерит composable в PNG на
JVM и сравнивает с эталоном. Ложится на уже готовые stateless-экраны почти даром:

- плагин в `:core:ui` (`app.cash.paparazzi`);
- тест вызывает `FirstScreen(...)` с теми же sample-данными, что и превью;
- `recordPaparazzi` фиксирует эталоны, `verifyPaparazzi` проверяет в CI.

Не подключил сразу, чтобы не тащить в первый синк ещё одну версионную зависимость;
скажи — добавлю с закреплённой версией.

## Что чем ловить

| Меняешь | Бери |
|---|---|
| Вид экрана/пузырьков, тему, отступы | Preview (1), потом Paparazzi (4) |
| Логику флоу, Back, обработку результата | Sandbox + Apply Changes (2) |
| Классификацию, вывод графа, модель | Unit-тесты (3) |
| Манифест, Hilt-граф, DI-сигнатуры | Полный Run (переустановка неизбежна) |
