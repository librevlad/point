# Point — операционная модель разработки

Как здесь организована работа: три «кресла», их права решений, петля одного среза и
где живёт контекст. Инженерные инварианты — в `CLAUDE.md`; направление — в
`ROADMAP.md`; спорные развилки — в `DECISIONS.md`. Тут — *ритм*, а не бюрократия
(документ намеренно ≈ на один экран).

## Три кресла

| Кресло | Владеет | Решает | Пишет | Никогда |
|---|---|---|---|---|
| **ChatGPT — ко-фаундер / продукт** | ЧТО и ЗАЧЕМ | Скоуп, приоритет, ship/no-ship по Северной звезде | **Issues** (скоуп + acceptance + чем уменьшает переключения); порядок «Up next» | Прод-код; открывать/мёржить PR; менять `compileSdk`/зависимости |
| **Claude Code — CTO / dev** | КАК | Архитектура, реализация, инвариантные развилки | **Ветка + PR** (self-review, чеклист инвариантов, результат гейта); записи `DECISIONS.md`; коммиты | Решать приоритет; **начинать срез без «go»**; self-merge без зелёного CI |
| **Человек (librevlad) — founder/owner** | ВКУС + ГЕЙТ | «go», финальный approve, **merge**, тег релиза | Сигнал «go»; approve/merge PR; ратификация спорных DECISIONS | Микроменеджить «как» |

**Граница в одну строку:** ChatGPT — *что стоит делать и зачем*; Claude — *как это
построено, и строит*; человек — *go / не сейчас* и *merge / держим*.

## Права решений: что / как / делать

- **Что и зачем** — ChatGPT. Превращает `ROADMAP.md` в скоупнутые issues, держит
  порядок «Up next», защищает Северную звезду («каждый релиз уменьшает переключения
  между приложениями»).
- **Как** — Claude Code. Реализация за контрактами, инварианты `CLAUDE.md`, спорные
  развилки → `DECISIONS.md`.
- **Делать / не сейчас** — человек. Единственный, кто даёт «go» и мёржит.

## Петля одного среза

1. **Направление → задача.** ChatGPT читает `ROADMAP.md` → пишет **Issue** (acceptance
   + одна строка про Северную звезду) → Backlog/Up next.
2. **Приоритет + «go».** ChatGPT упорядочивает «Up next». Человек даёт **«go»** на
   верхний issue (`roadmap #N` — это *идентичность*, не приоритет).
3. **Сборка.** Claude: issue → In progress; ветка `feat/N-slug`; реализация; инварианты;
   при спорной развилке — `DECISIONS.md`; гейт `./gradlew test assembleDebug`; независимое
   AI-ревью `bash scripts/gemini-review.sh`; **PR** (Conventional-title, `Closes #N`,
   чеклист) → In review.
4. **Суд.** Человек смотрит diff (вкус + Северная звезда), ждёт **зелёный CI**,
   **squash-merge**. Issue авто-закрыт → Done.
5. **Релиз (периодически).** Прошёл milestone по Северной звезде → человек режет тег.

**«go» = переход доски `Up next → In progress`.** Это конкретный триггер правила
`CLAUDE.md` «не начинай следующий срез без явного го». ChatGPT, заскоупивший issue, —
это НЕ «go»; «go» даёт только человек.

## Где живёт контекст (без двойного учёта)

| Артефакт | Что держит | Кто пишет / читает |
|---|---|---|
| `docs/ROADMAP.md` | Стратегия/нарратив: Северная звезда, фазы, швы (не статус задач) | ChatGPT/человек пишут; Claude читает |
| **GitHub Issues** | Исполняемые задачи: скоуп, acceptance, статус, обсуждение | ChatGPT пишет; Claude ссылается; закрывает merge |
| **Projects-доска** | Текущее состояние (какой issue где) | авто (workflow «closed → Done») |
| **PR-описание** | «Как в полёте»: self-review, инварианты, гейт | Claude пишет; человек читает для approve |
| `docs/DECISIONS.md` | Долговечные спорные решения | Claude добавляет; человек ратифицирует |

Новые гранулярные задачи **рождаются как Issues** (#7+), не дописываются в `ROADMAP.md`.

## Ветки и PR

- Ветка: `<type>/<issue#>-<slug>` (напр. `feat/5-floating-bubble`), type = Conventional-тип.
- **PR** на существенное (новый Capability/Realizer, архитектура, всё, что трогает
  инвариант, мультифайловое); **прямо в `main`** на тривиальное (`docs:`/`chore:` вне
  `src/main`). Сомневаешься → ветка. CI гоняется и на прямых пушах.
- **Squash-merge** только при зелёном CI (`gh pr merge --squash --delete-branch`) —
  держит историю линейной. PR-title = Conventional-Commit subject + `Closes #N`.
- Жёсткая branch protection отложена (блокирует соло self-merge); включить с приходом
  2-го контрибьютора.

## CI

Один workflow `.github/workflows/ci.yml`: `./gradlew test assembleDebug` на каждый push
в `main` и на PR. Билд keyless (без секретов) — гард в `data/build.gradle.kts`.

## Ревьювер (Gemini CLI)

Независимый AI-ревьювер — второе мнение помимо CTO/dev, локально и read-only.
`bash scripts/gemini-review.sh [base]` (база по умолчанию `origin/main`) берёт дифф
ветки и шлёт в **Gemini CLI** (`--approval-mode plan` — только чтение; модель
`gemini-flash-latest`, т.к. дефолтная `gemini-2.5-pro` недоступна на free-tier), печатает
ревью с упором на инварианты проекта. Ключ — из `local.properties` (`GEMINI_API_KEY`),
в репозиторий не попадает. Claude прогоняет его перед PR; вывод **информативный, не гейт**
(гейт — зелёный CI + вкус человека).

## Релизы

Ручной тег-на-milestone под Северную звезду: `git tag -a vX.Y.Z` + опц. `gh release
create --generate-notes`. В том же коммите — синхро `versionName`/`versionCode`
(`app/build.gradle.kts`). CHANGELOG не ведём (Conventional Commits + generated notes).

## Инварианты

Не дублирую — единственный источник правды по инженерным инвариантам (Capability ≠
Realizer, Android-free ядро, side-effect за контрактом, ≤300 мс первый экран, …) —
`CLAUDE.md`, раздел «Инварианты, которые легко нарушить».
