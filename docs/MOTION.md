# Point Motion & Sensory Language

Не UI-kit — **язык взаимодействия** (владелец, коммент к #114). Если Point хочет ощущаться
новым слоем поверх ОС, он не может выглядеть как ещё одно Material-приложение. Этот документ —
первоисточник сенсорного языка: принципы, их маппинг на текущий код и нарезка на срезы.

**Правило-зонтик:** *каждое действие приносит микроскопическую радость.* Даже «Скопировать».
Анимация + тактильный отклик + (опционально) фирменный звук. Это acceptance-критерий каждого
motion-среза, не отдельная фича.

## Принципы → состояние → срез

| # | Принцип | Что уже есть | Чего нет | Срез |
|---|---------|--------------|----------|------|
| 1 | Ничего не появляется мгновенно — всё **рождается** | stagger fade/scale пузырей; построчное рождение фактов «Понял» | «вдох» объекта перед волной пузырей | M2 |
| 2 | **Объект живой** (фото покачивается, PDF имеет глубину, QR светится) | — | дыхание/глубина/свечение по типу | M1 |
| 3 | Point **думает** — не спиннер, а импульсы | карточка растёт по мере находок; строка «Распознаю текст…» со спиннером | заменить спиннер на световые импульсы по объекту | M1 |
| 4 | Bubble — **частицы**: притягиваются к объекту, а не выезжают | scale-in на месте | появление траекторией от объекта; уход обратно в объект при запуске | M2 |
| 5 | **Фон никогда не статичен** (медленный mesh-gradient, «дорого») | статичный фон | AGSL-шейдер (API 33+) + статичный фолбэк | M5 |
| 6 | У каждого объекта **своя физика** (фото мягкое, документ строгий…) | — | параметры анимаций от `ObjectKind` | M1/M2 |
| 7 | У каждого действия **свой звук** (тихий, «как у Leica») + хаптика | — | SoundPool: 3–4 фирменных сэмпла + `performHapticFeedback`; выключаемо, по умолчанию вкл | M4 |
| 8 | Экраны **перетекают**, объект всегда в центре | AnimatedContent fade/scale по id объекта; таймлайн стоит на месте | морф самого объекта между состояниями | M3 |
| 9 | **Трансформация — шоу** (300–500 мс: фото складывается в страницу → стопку → PDF) | — | хореография для 2–3 знаковых переходов (image→PDF, text→PDF, OCR) | M3 |

## Нарезка (каждый срез — демонстрируем за 30 секунд)

- **M1 «Живой объект и аура»** — дыхание превью (масштаб ±0.5%, медленно), физика по
  `ObjectKind` (амплитуда/жёсткость), импульсы понимания вместо спиннера (пульсирующее кольцо
  по хедеру, пока `enriching` непуст), аура-свечение при первом факте. Чистый Compose
  (`InfiniteTransition`), ноль зависимостей.
- **M2 «Пузыри-частицы»** — появление: от центра объекта по короткой дуге (spring, stagger);
  запуск действия: пузырь утягивается в объект; latent-пузыри дрейфуют на ±2dp. Идея #115
  (drag-объекта-к-пузырю) — отдельное исследование, сюда не входит.
- **M3 «Трансформация-шоу»** — общий морф хедера (иконка/превью старого типа перетекает в
  новый, 300–500 мс) + персональная хореография image→PDF («складывание в страницу») и
  OCR («буквы проступают»). Вместо BusyScreen для локальных быстрых действий.
- **M4 «Звук и хаптика»** — контракт `SensoryFeedback` (:core:flow) → реализация :data
  (SoundPool + Vibrator); 3–4 сэмпла (tick/whoosh/pulse, CC0 или сгенерённые), карта
  «capability-тир → отклик»; настройка выключения рядом с ключами; Done-результаты получают
  хаптику всегда, звук — по настройке.
- **M5 «Живой фон»** — очень медленный mesh-gradient (AGSL `RuntimeShader`, API 33+;
  статичный градиент как фолбэк), пауза при неактивности окна (батарея).

Порядок: M1 → M2 → M3 (ядро ощущения), M4 и M5 — независимые, в любой момент после M1.

## Инварианты (не нарушать анимациями)

- **≤300 мс до интерактивного первого экрана**: язык украшает готовый экран, никогда не
  задерживает его. Никаких блокирующих enter-хореографий.
- **Уважение системы**: `Settings.Global.ANIMATOR_DURATION_SCALE == 0` (reduced motion) →
  вся динамика статична; звук — только при включённой настройке.
- **Батарея**: infinite-анимации живут только пока окно в фокусе; фон (M5) — 1 шейдер, без
  постоянной перерисовки всего дерева.
- **Никакой физики поверх смысла**: движение объясняет модель (объект → возможности →
  превращение), а не украшает. Если анимацию нельзя объяснить принципом из таблицы — её нет.
