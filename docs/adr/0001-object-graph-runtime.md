# ADR-0001. Object Graph Runtime

**Статус:** принято владельцем 30 июля 2026.
**Основание:** манифест архитектуры (владелец) + консилиум восьми внешних моделей
(`docs/designs/document-engine-v3.md`) + сверка с фактическим состоянием ядра.

## Фундаментальная цепочка

Менять только новым ADR:

```
PointObject → Extractor → PointObject Graph → Planner → Action → Executor → PointObject Graph
```

Свободно расширяется без ADR: `PointObject.kind`, Actions, Executors, Extractors, реализации,
LLM, OCR, OpenCV, ICG.

Философия: Point — универсальная правая кнопка для любого объекта. Он **не классифицирует
документы**, а постепенно превращает входной объект в граф более простых и более полезных
объектов. Именно здесь архитектура отделяется от OCR-систем: не `фото → CMR → ветка if`, а
`фото → атомы → простые сущности → ещё более простые → Capability`.

## Что уже соответствует манифесту

`PointObject` (`core/model/.../PointObject.kt`) уже несёт `sourceObjects` и `creatorAction` —
рёбра происхождения графа появились в #225. `uri` уже `ObjectRef`, а не байты. Вывод пузырьков
уже не хранит таблицу переходов: Action доступен всем подходящим объектам через `accepts` —
инвариант «Flow Graph выводится, не хранится». `EnrichmentDelta` уже несёт объекты и связи (#226).

Карта имён — манифест против кода. Решено **оставить имена в коде как есть**: владелец в
обсуждении пользуется словом Capability, и переименование ради словаря не стоит blast radius.

| Манифест | Код |
|---|---|
| Action | `Capability` (декларация: `accepts` / `produces` / `meta`) |
| Executor | `Realizer` за `Resolver`, включая `FallbackRealizer` |
| Planner | `BubblePolicy` / `LearningBubblePolicy` |

Правило «пользователь никогда не знает о Capability» относится к тому, что видно на экране:
человек видит подпись пузырька, не имя класса. Это соблюдается сегодня.

## Поправка 1. Происхождение вместо уверенности

`confidence: Float` уходит из ядра. Одно число не работает: уверенность несравнима между
ридерами — это self-assessed probability, а не измеренная точность (подтверждено практикой
Textract, Google DI, Azure DI). Вместо него:

```
Provenance {
    source: OCR | LLM | RULE | HUMAN
    evidence: [...]      // адреса атомов, подписи-улики, сработавшие правила
    alternatives: [...]  // другие прочтения того же места
}
```

Point **не принимает решение «верить или нет»** — он хранит происхождение и показывает его.

Что это ломает и чем заменяется: сегодня `confidence` драйвит знак ⚠ и механизм консенсуса.
Знак ⚠ становится производным от происхождения — **одного класса доказательств достаточно для
предположения, но не для подтверждения** (два независимых класса из пяти: геометрическое,
лексическое, структурное, семантическое, арифметическое). Консенсус переезжает в `alternatives`:
«трек найден, но есть второй похожий номер» вместо ложной однозначности. Правка человека
(`source = HUMAN`) не переписывается прилетевшим позже ответом модели — инвариант из #243.

**Реализовано (#264), с одним отклонением от буквы.** `Provenance` — `enum` в `:core:model`
(`GIVEN | MODEL | RULE | OCR | HUMAN`, порядок объявления = сила), а не структура из трёх полей:
`evidence` и `alternatives` **уже** живут собственными контрактами — `EvidenceClass` + `<key>.ev`
(#261) и `<key>.alt` / `<key>.more` (#260). Склеить их обратно в одну структуру значило бы
завести третий источник истины о том же самом. Поле `PointObject.provenance` — типизированная
проекция аннотации `<key>.src`, единственного автора; направление вывода всегда `metadata → field`,
поэтому происхождение переживает журнал бесплатно. Подробности и следствия — в `docs/DECISIONS.md`.

## Поправка 2. Атом не является узлом графа

**Атом никогда не существует вне родительского объекта.** Он адресуем, но не живёт отдельно.

Атом — слово или спан с polygon, уверенностью ридера и версией ридера; на одной странице их
тысячи. Если каждый станет узлом DAG, фото породит трёхтысячный граф — это убивает и память, и
UX. Атомы живут внутри объекта отдельным слоем улик:

```
PhotoObject
└── OCRLayer
    ├── Atom
    ├── Atom
    └── …
```

Граф про `Atom` не знает. Узлом становится то, что имеет смысл для человека: трек-номер, а не
слово.

## Поправка 3. `Done` — официальное исключение

Правило «любая обработка создаёт новый объект» **не распространяется на Capability с внешним
побочным эффектом**. Share ничего не создаёт внутри Point — он меняет внешний мир. Рожать
`ОтправленноеСообщение` ради формального соблюдения правила запрещено.

Формулировка: **Side-effect Capability имеют право вернуть `Done`.** `ActionResult.Done`
остаётся как есть; Share, Save и «продолжить на ПК» — его законные пользователи.

Это решение владельца против первоначальной рекомендации создавать объекты, и оно
зафиксировано именно как решение, а не как недоделка.

## Поправка 4. Формат — представление, а не объект

Смысл и способ его выдать — разные уровни. Сегодня из таблицы рождаются `Table`, `Excel`, `CSV`
как независимые объекты с расходящимися правками. Правильно:

```
TableObject (семантический объект)
└── RepresentationCache: xlsx? · csv? · tsv? · html?
```

Одно и то же значение не может существовать в графе трижды под разными расширениями.
`ExportExcel` и `ExportCsv` — это Actions, дающие **представление** существующего объекта, а не
новую сущность.

**Представление ленивое.** Это не список, который обязан быть заполнен, а кэш: представления
может не быть вовсе, оно может появиться позже и может быть вытеснено. Ни один xlsx не обязан
существовать только потому, что объект — таблица. Формулировка важна: список создаёт впечатление,
что все представления должны быть материализованы, и тогда каждый экспорт превращается в
обязательство хранить файл.

## Правило принадлежности графу

Критерий, отвечающий на вопрос «становится ли сущность узлом графа» без обсуждений:

> **PointObject обязан быть полезен пользователю сам по себе.**

Если человек не может осмысленно увидеть объект, выбрать его и применить к нему Capability —
это внутренний слой реализации, а не узел графа.

Проходят: `TTN`, `Phone`, `Address`, `Table`, `Person`, `Money`, `Weight`, `QR`.
Не проходят: `WordAtom`, `BoundingBox`, `OCRLine`, `Paragraph`.

## Что хранит граф и сколько он живёт

«Никакой объект не уничтожается» и «по окончании флоу обязательный `ObjectStore.clear()`»
несовместимы, пока граф хранит байты. Решение: **граф не хранит payload** — как Git.

Но «граф хранит ссылки» — формулировка неточная и опасная: под неё начнут складывать служебные
поля в `ObjectRef`, пока он не станет свалкой. Граф хранит ровно пять вещей:

```
Identity     — id, kind
Relations    — рёбра происхождения и связи между объектами
Metadata     — факты объекта
Provenance   — источник, улики, альтернативы
ObjectRef    — и ничего, кроме ссылки на payload
```

`ObjectRef` — это адрес и только адрес. Всё, что не адрес, живёт в четырёх остальных полях.

Следствие, обязательное к исполнению: `ObjectRef` должен быть **восстановимым**, а не только
валидным. Объект помнит, откуда он взялся, и умеет перечитать себя; тяжёлые payload'ы
вытесняются, история весит килобайты, а не гигабайты. Именно это делает атомы с координатами
обязательными, а не желательными: без адреса перечитать нечего.

## Инвариант: PointObject неизменяем

После создания объект **никогда не редактируется**. Ни при каких обстоятельствах не бывает
`photo.weight = …`. Есть только порождение:

```
Photo → Photo′ → Photo″        (новая версия того же объекта)
Photo → Table                  (новый объект, связанный происхождением)
```

Это резко упрощает lineage, происхождение, кэш, восстановление, дедупликацию и синхронизацию с
ПК — и делает граф по-настоящему ациклическим, а не «почти».

**Что это значит для существующего кода, и это не косметика.** На уровне значения `PointObject`
уже неизменяем — Kotlin `data class` со всеми `val`. Недостающая часть — **версионность в
графе**: обогащение (`EnrichmentDelta`, слияние фактов из #226, #231, #243) обязано порождать
**новую версию** объекта, а не подменять текущую. Идентичность и происхождение остаются
стабильными, версии дописываются, UI показывает голову цепочки.

Побочный подарок: инвариант #243 («обогащение добавляет факты, но не переписывает установленные
человеком») выполняется тогда сам собой — переписывать нечего в принципе, поздний ответ модели
создаёт следующую версию, а правка человека выигрывает политикой чтения, а не порядком записи.
И прогрессивное наливание результата, о котором договаривались раньше, становится честной
цепочкой версий вместо гонки за одно поле.

## ExecutionPolicy: цена принадлежит запуску, а не Extractor'у

Правило обязательно, иначе манифест молча отменяет два действующих инварианта: **первый экран
≤300 мс без сети** и **никаких автоматических цепочек**. Манифест разрешает Extractor'у
использовать LLM и говорит, что обработка расширяет граф; вместе это означает, что граф растёт
сам, по сети и за деньги.

Но цену объявляет не Extractor. Extractor — это код, и один и тот же OCR бывает офлайновым на
одном устройстве и облачным на другом; цена зависит от того, **как его запустили**, а не от того,
что он умеет. Поэтому цена — свойство запуска, `ExecutionPolicy`, и живёт она там, где делается
выбор исполнителя, то есть у `Resolver`. Уровней ровно три:

1. **Бесплатный, офлайн, мгновенный** — работает сам, дешёвая волна: MIME, расширение, размер,
   затем OCR и атомы.
2. **Дорогой или сетевой** — не запускается никогда без явного тапа по Action. Здесь живёт
   модель-искатель (#257–#261).
3. **Перечитывание по кропу** — только по сомнению, конфликту валидатора или выделению человека.

Без этого правила объект, который человек просто открыл посмотреть, сжигает квоту.

Это не про производительность, а про доверие: **открыть объект не должно означать потратить деньги.**

## Следствия для кода

- `PointObject.confidence: Float` → `provenance: Provenance` (сделано в #264). Затрагивает
  `core/model` и подпись найденного объекта в UI; улики и альтернативы **остаются своими
  контрактами** (`<key>.ev`, `<key>.alt`/`<key>.more`) и в `Provenance` не переезжают, а
  «возможно» на экране вычисляется из них, а не наследуется от числа.
- `TesseractTextRecognizer.recognize(): String` → спаны с геометрией; атомы как слой внутри
  объекта, не узлы (#257).
- Адрес значения = множество атомов, id от модели валидируются против индекса (#258).
- Представления вместо объектов-форматов: `ExcelAction`, `SpreadsheetFormat`, `WordAction`.
-  у : дешёвая волна остаётся в ≤300 мс, сетевое — только по тапу.
- Обогащение порождает версию объекта, а не подменяет его: затрагивает  и слияние фактов (#226, #231, #243).
- Представления — ленивый кэш, а не обязательный список.

## Что этот ADR не меняет

Ни один из действующих инвариантов не отменяется: `:core:model` и `:core:flow` остаются
Android-free; каждый side-effect за интерфейсом; результат шага — sealed `ActionResult`; объект
копируется в scratch немедленно; Point не строит автоматических цепочек; LLM не на первом
экране. Порядок срезов #257–#263 не меняется — атомы всё равно первые, потому что без них у
графа нет адресов, а у объектов — происхождения.
