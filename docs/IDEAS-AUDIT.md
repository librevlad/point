# Разбор идей — сверка с кодом, вердикты

Проход по всем открытым issue без меток (заметки-идеи, не задачи), 2026-07-29.
Метод: прочитать идею целиком → **ретроспектива по git** (что из неё уже построено) →
трезвая оценка остатка по коду → вердикт: **отбросить** или **распланировать с критериями**.

Правило: идея без вердикта остаётся идеей. Идея с вердиктом становится либо закрытой
записью, либо задачей спринта с критерием приёмки.

## #79 — «Неявное связывание топологий» + «Декапсуляция намерений»

**ВЕРДИКТ: ЗАКРЫТЬ ЦЕЛИКОМ.**

Идея распадалась на три части.

**79.A — синтез совместимости через трансформацию. ✅ ПОСТРОЕНО** — `9e4b19c`,
`FlowViewModel.kt:680`. «Открыть в…» предлагает приложения, достижимые через ОДНУ
трансформацию (image→PDF, image→text), помечает их «`<App> · PDF`», по тапу выполняет
трансформацию и запускает конвертированный объект. Глубина 1, на устройстве, без бэкенда.
`AppLauncher.handlersForMime()` находит достижимые приложения до появления объекта.
Ядро идеи — «Point синтезирует совместимость там, где разработчики её не закладывали» —
доказано в бою.

**79.B — синтез через локальный сервер** (file:// → localhost URL → Cast на ТВ). Отброшено.
Бьётся в два инварианта проекта: трансляция живёт дольше флоу (против обязательного
`ObjectStore.clear()`) и требует foreground service (против «терминальные действия без
Activity»), а FGS на `targetSdk 36` требует объявленного типа и обоснования в Play Console.
Ценность узкая — Cast видео на телевизор.

**79.C — декапсуляция намерений** (`startService`/`sendBroadcast` вместо `startActivity`).
Отброшено — **платформа не даёт**, дело не в объёме работы. `startService()` в чужое
приложение из фона запрещён с Android 8; чужой сервис или ресивер должен быть `exported`,
что с Android 12 редкость и требует явного разрешения; deep link всё равно открывает
приложение, то есть headless не получается. Косвенное доказательство в самом репозитории:
у Point ровно один экспортированный сервис, и тот закрыт `BIND_QUICK_SETTINGS_TILE`.

## #82 — «Бэкенд как единый хаб»

**ВЕРДИКТ: РАСПЛАНИРОВАТЬ НА 0.4.** Ретроспектива: 0 коммитов.

Не случайная идея, а **структурный ответ на главный блокер релиза**. B1 (семь секретов
в артефактах) существует ровно потому, что токены живут в клиенте. Решающий аргумент,
которого нет в тексте идеи: **сегодня ротация сгоревшего free-ключа требует выпуска нового
APK** — то есть тезис «жить на бесплатных ресурсах и ротировать» на клиенте физически
неисполним. На сервере это правка конфига.

Дешевле, чем кажется: оркестрация уже написана (`FallbackLlmClient`, 8 провайдеров,
~24 модели, `DataModule.kt:366-371`) — это перенос, а не стройка. Заодно убирает дубль:
LLM-клиент живёт в двух местах, и `:bot` (`BotLlm.kt:50`) знает **только Gemini без фолбэка**,
то есть умирает на первом 429.

**Критерии приёмки:** ни одного провайдерского ключа ни в одном раздаваемом артефакте ·
сгоревший ключ меняется на сервере без выпуска клиента · свежая установка делает AI-действие
без BYOK · логика фолбэка в одном месте, не в трёх · квота на устройство.
**Проверить перед стартом:** доступность Oracle free-tier A1 ARM (была нехватка ёмкости).

## #83 — «ICG: полный серверный стек»

**ВЕРДИКТ: ОТБРОСИТЬ СТЕК. ICG остаётся фазой 4 роадмапа.** Ретроспектива: 0 коммитов,
и ноль из восьми предложенных технологий в репозитории.

Причины: уничтожает главный рычаг проекта (`:bot` и `:desktop` зависят только от
`:core:model` + `:core:flow`, чистый Kotlin — поэтому обошлись почти даром; Python-ядро
и Rust-десктоп лишают ядро переиспользуемости) · восемь инновационных токенов сразу в
невыпущенном продукте · CRDT решает проблему, которой нет (объект переезжает, его не правят
одновременно с двух сторон) · шов под ICG уже есть и стоит ноль — `RealizerMeta.kt:16`,
`RealizerKind { LOCAL, CLOUD, REMOTE }` · полезное ядро уже поглощено #82.

## #91 + #93 — «Telegram как шина возможностей»

**ВЕРДИКТ: #93 ЗАКРЫТЬ КАК ДУБЛЬ #91. #91 ОТЛОЖИТЬ ЗА ICG с условиями входа.**
Ретроспектива: 0 коммитов у обеих. Это одна и та же идея, записанная дважды.

Архитектурно ложится идеально — чужой бот это ровно `RealizerKind.REMOTE`. Против:
бот не пишет первым (пользователь сам должен его запустить и дать право) · чужой бот меняет
формат и Capability молча ломается, без версии и SLA · объект уходит третьей стороне,
о которой Point ничего не знает, в продукте с экраном согласия.

**Условия входа:** контракт ответа с версией · явное согласие на конкретную третью сторону ·
видимая человеку ошибка при поломке чужого бота.
